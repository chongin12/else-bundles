# else-bundles

else 앱의 **추천 else** 카탈로그. GitHub Pages로 `catalog.json` 하나를 서빙한다.
앱은 이 파일을 읽기만 한다. 형식과 검증 규칙은 else 통합 스펙 §6.24.1이 기준이다.

## 형식 (`schema: 1`)

```json
{
  "schema": 1,
  "bundles": [
    {
      "id": "2026-11-moving",
      "language": "ko",
      "title": "이사 준비",
      "icon": "📦",
      "summary": "이사 한 달 전부터 챙길 것",
      "items": [
        { "title": "전입신고", "memo": "이사 후 14일 이내\n정부24: https://www.gov.kr" },
        { "title": "인터넷 이전 신청", "date": "2026-11-20" }
      ]
    }
  ]
}
```

## 작성 규칙

- **`id`는 `YYYY-MM-주제`로 짓고, 한 번 쓴 id는 다시 쓰지 않는다.** 앱의 "본 것"·"가져온 것"
  기록이 id에 묶인다.
- 같은 `id`가 두 번 나오면 **뒤의 묶음이 버려진다.**
- `id`에는 쉼표(`,`)를 쓰지 않는다. 앱이 새 묶음 팁을 식별할 때 id를 쉼표로 이어 붙인다.
- `language`는 반드시 적는다(`ko` / `en`). 앱은 자기 언어의 묶음만 보여 준다.
- 묶음 하나는 **1~20개** 항목. 날짜는 `YYYY-MM-DD`. 하나라도 어기면 앱이 그 묶음을 통째로 버린다.
- 아이콘은 이모지 한 글자. 이모지 한 글자가 아니면 **묶음을 버리지 않고** 기본 ◦로 보인다(다른
  규칙과 다르다).
- **`schema`는 같은 주소에서 올리지 않는다.** 새 형식은 새 경로(예: `catalog-v2.json`)에 두고
  `catalog.json`은 `schema: 1`로 남긴다. 옛 앱은 자기가 아는 주소만 읽는다.
- **모집공고 원문을 복사하지 않는다.** 메모에는 요약과 공식 공고 링크만 적는다.
- 공공데이터로 만든 묶음은 그 데이터의 이용허락 조건(출처 표시 등)을 따른다.
- 정정이 사용자에게 닿기까지 **최대 6시간 남짓** 걸린다(Pages 캐시 + 앱 간격). 그 안에 반드시
  닿아야 하는 정보는 올리지 않는다.
- 지난 묶음은 앱이 알아서 숨긴다(날짜 있는 항목이 전부 지나면). 정리는 분기마다 한다.

## 올리기 전에 앱에서 미리 보기

```bash
python3 -m http.server 8000
```

DEBUG 빌드를 `-debug.recommendedCatalogURL http://127.0.0.1:8000/catalog.json` 인자로 실행한다.
호스트는 `localhost`가 아니라 IP로 적는다(ATS). DEBUG에서는 6시간 간격을 건너뛴다.
